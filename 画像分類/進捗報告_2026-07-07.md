# 進捗報告（2026-07-07）画像分類班

前回の報告で「学習に使っている劣化フィルタは、本物の reCAPTCHA の劣化として妥当なのか」と指摘を受けた。今回はこれに本物のデータで答えるところから始めて、精度の現在地まで報告する。

---

## 1. 使用モデル

ResNet18（torchvision の ImageNet 事前学習済みモデル）を2通りの使い方で比較している。

- **zero-shot**：追加学習を一切せず、ImageNet 1000クラスの出力から bus 関連クラスの確信度を取り出して「バスっぽさ」のスコアにする。学習なしでどこまでいけるかの基準になる。
- **fine-tuned（FT）**：最終層を bus / other の2クラスに付け替えて学習し直したもの。学習データは COCO 2017 から集めたベース画像 300枚/クラスに、後述の劣化フィルタ2種をかけて3倍に水増しした計900枚/クラス。シードは42固定、10エポック回して bus の F1 が最も良かったエポックの重みを採用している。Mac の MPS で数分で終わる。

判定対象は reCAPTCHA の1マス分の画像で、「バスか、そうでないか」の2値。どのマスにあるかを当てる物体検出は別班の担当なので、こちらでは扱わない。

## 2. 目標判別精度（フィルタの妥当性も）

### 目標と現在地

目標は、本物の reCAPTCHA 画像で人間の正答率（文献値でおよそ82%とされる）に並ぶこと。

評価指標は AP（PR曲線の下の面積）を使っている。モデルは画像ごとに0〜1のスコアを出すので、「どこ以上を選ぶか」の閾値を端から端まで動かしたときの適合率と再現率の面積が AP になる。閾値の選び方に依存せずモデルの力を1つの数で表せるので、スコアの作り方が違う zero-shot と FT を同じ軸で比べられる。

| 評価データ | 正例/負例 | zero-shot AP | fine-tuned AP | 差 |
|---|---:|---:|---:|---:|
| 晴れの通常写真 (img) | 11/99 | 1.000 | 0.984 | −0.016 |
| 雨の写真 (img_bus_rain) | 50/52 | 0.978 | 0.943 | −0.035 |
| 本物 reCAPTCHA (real_recaptcha) | 6693/6693 | 0.875 | **0.906** | **+0.031** |

劣化のないきれいな写真では zero-shot が勝つ。ImageNet で大量のバスを見てきたモデルなので、きれいな写真なら追加学習の余地がほぼ無い。ところが本物の reCAPTCHA 画像（低解像度でノイズだらけ）では FT が逆転して上回る。この逆転は、劣化つきで学習したモデルなら旧フィルタ版でも新フィルタ版でも一貫して出ており（差は +0.021〜+0.036）、偶然の1回ではない。

F1 で見ると、本物データでの FT の最大F1は 0.827。F1 は適合率（選んだうち本当にバスだった割合）と再現率（バスを取りこぼさなかった割合）の調和平均で、目標にしていた人間の82%とほぼ同じ水準まで来た。ただし2点、正直に断っておく。

- この 0.827 は閾値を動かして一番良かった点の値なので、少し楽観的な数字になる。実運用では閾値を検証データで先に決める必要がある。
- 人間の82%は正答率で、こちらは F1。評価セットが正負1:1なので大きくはずれないが、厳密に同じ物差しではない。なので「上回った」ではなく「並んだ」と言うに留める。文献の出典は現在確認中。

差が本当に意味のある差なのかも確かめた。評価画像13,386枚から復元抽出でサンプルし直して AP の差を測り直す、ということを1万回繰り返すと（ブートストラップ法）、差がどれくらいぶれるかの範囲が出せる。本物データでの FT−zero-shot の差の95%区間は [+0.015, +0.027] で、0を跨がなかった。つまり評価画像の引きが良かっただけ、という可能性は否定できる。

### フィルタの妥当性（前回指摘への回答）

前回のフィルタは「暗くする＋白い線を描く」で夜と雨を模していた。妥当かどうかを調べるため、まず本物を見た。

1. 実際の reCAPTCHA v2 から取られた実画像29,568枚のデータセット（HuggingFace の recaptchav2-29k）を導入して目視で確認した。本物の劣化は低解像度とぼけと JPEG のブロックノイズで、雨だれの線も夜の暗さも入っていない。旧フィルタは的外れだった。
2. そこでフィルタを、低解像度化＋ぼかし＋彩度低下＋JPEG 低品質再圧縮に作り直した。
3. どちらが本物に近いかは FID で測った。FID は2つの画像集合の特徴分布の距離で、小さいほど似ている。同じクリーンなバス画像にフィルタだけ変えてかけ、本物のバス画像6,693枚との距離を比べた。

| フィルタ | FID（小さいほど本物に近い） | 判定 |
|---|---:|---|
| clean（劣化なし、基準） | 206.7 | — |
| 旧・夜（暗く） | 179.2 | 少し近づく |
| 旧・雨（暗く＋白線） | 381.5 | 逆効果。本物に無い線で遠ざかる |
| 新（低解像度＋ぼけ＋JPEG） | **164.5** | 最も近い |

雨フィルタに至っては劣化なしより本物から遠ざかっていた。新フィルタが最も近く、作り直しは妥当だったと言える。

フィルタが精度にどう効いたかは、劣化条件だけ変えた学習で切り分けた。劣化なし（原本のみ）で学習すると本物データで AP 0.842 まで落ち、zero-shot の 0.875 にすら負ける。劣化つきの水増しをすると 0.896〜0.911 まで上がるので、水増し自体が効くことははっきりした。ただし旧フィルタと新フィルタの間の差は、同一条件で2回学習したときのぶれ（±0.015程度あることが分かった）に埋もれていて、「新フィルタだから AP が上がった」とまでは今は言えない。フィルタが本物に似ていること自体は FID で示せているので、精度への寄与は複数シードの学習で次回決着させる。

## 3. テスト・学習データの分離

分離は3段階でやっている。

まずソースの分離。学習は COCO 由来の画像と、それに合成劣化をかけたものだけ。評価は別ソースの本物画像3セット（晴れ、雨、本物 reCAPTCHA）で、評価画像は学習に1枚も使っていない。合成劣化は学習の水増し専用で、評価側には混ぜない。ここを混ぜると「自作フィルタに過学習しただけ」の数字が出てしまう。

次に train/val のリーク防止。原本と劣化版2枚は同じ景色なので、ファイル単位でランダムに分けると同じ景色が train と val の両方に入り、val の点数が甘く出る。分割は元画像のID単位でやっていて、同一景色の3枚は必ず片側にだけ入る。

最後に再現性。シードは全て42固定、パッケージは uv.lock で固定していて、同じ手順を踏めば同じ分割と同じ学習結果になる。

## 4. 現在の問題点

1. **フィルタ種類の寄与が未決着**。上に書いた通り、同一条件でも学習のたびに AP が ±0.015 ほどぶれるため、新旧フィルタの差がその中に埋もれている。同一ベースで各3シード学習して比較するのが次の最優先。
2. **git 管理外の生成物がマシン間でずれる**。学習済みモデルと dataset/ は git に入れていないので、別マシンでの再学習が手元に反映されない。実際に今日、旧モデルを新モデルと取り違えて検証してしまう事故があった（発見して訂正済み。ドキュメントにも経緯を残した）。モデルファイルに学習日とデータ設定のメタ情報を持たせる対策を入れる。
3. **信頼区間の再計測**。ブートストラップの区間は旧フィルタモデルで測った値なので、現行の300ベースモデルで測り直して +0.031 に区間を付ける。
4. **評価セットが人工的に1:1**。本物セットは bus と nonbus を同数に揃えてある。実際の reCAPTCHA では bus の出現率はもっと低いので、AP の絶対値は実運用の値とは一致しない。zero-shot と FT の比較の公平性には影響しない。
5. **9マスの通しデモが未確認**。1枚を3×3に分割して各マスを判定する流れは既にあるので、本物画像で通して発表用の絵を作る。
6. **bus というお題の限界**。bus は zero-shot でほぼ足りてしまうので、FT の価値をもっと明確に見せるなら ImageNet に無い、あるいは弱いお題（消火栓、横断歩道、階段）への拡張を検討する。

## 補足：質問されそうな点と答え

**Q. なぜきれいな写真では FT が負けるのか。**
ImageNet 事前学習のResNetは元々バスを高精度で見分けられるので、きれいな写真では伸びしろが無い。むしろ少ないデータで学習し直した分だけ少し崩れる。FT の価値は劣化した本物ドメインでのみ出る、というのが今回の主結果。

**Q. 最大F1 0.827 は信用していいのか。**
閾値スイープの最良点なのでやや楽観的。閾値を事前に固定する運用ではもう少し下がる。AP（閾値に依存しない指標）でも FT が有意に勝っていることが本体で、F1 は人間との比較のための参考値。

**Q. FID の絶対値が大きいのはなぜか。**
COCO の街並みに写るバスと reCAPTCHA の切り抜きタイルでは被写体自体が違い、その分が距離に乗る。フィルタでは埋まらない部分なので、同じ画像に劣化だけ変えてかけた相対比較として使っている。なお標準の FID は InceptionV3 特徴だがここでは ResNet18 特徴。相対比較なので順位は変わらないと考えている。

**Q. 本物データを学習に使えばもっと上がるのでは。**
上がるはず。ただし評価に使っている分と混ざるとリークになるので、画像ID単位で厳密に分けてから。今回は「合成の水増しだけでどこまで本物に転移するか」を先に確定させたかった。

**Q. データの出どころは問題ないか。**
recaptchav2-29k は MIT ライセンスだが画像自体は Google 所有で、非営利の教育研究目的に限定されている。画像は git に入れず再配布もしない。目的は分類手法の研究で、CAPTCHA 突破の実運用ではない。
