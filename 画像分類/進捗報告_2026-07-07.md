# 進捗報告（2026-07-07）画像分類班

前回（6/25）の指摘「学習に使う劣化フィルタは本物として妥当なのか？」に、本物データで答えるのが今回のテーマ。

---

## 1. 使用モデル

- **ベース**：ResNet18（ImageNet事前学習済み、torchvision）。
- **zero-shot**：ImageNet 1000クラスのまま使い、bus 関連クラスの確信度を「バスっぽさスコア」にする（学習なしの比較基準）。
- **fine-tuned（FT）**：最終層を bus / other の2クラスに付け替えて微調整。
  - 学習データ：COCO 2017 由来のベース画像 **300枚/クラス** ×（原本＋劣化2種）= 900枚/クラス。
  - シード42固定・10エポック・bus の F1 が最良のエポックを採用（Mac MPS で数分）。
- 判定対象は reCAPTCHA の1マス画像。「バスか／そうでないか」の2値判定（マスの位置当ては物体検出班の担当）。

## 2. 目標判別精度（フィルタの妥当性も）

### 目標と現在地

**目標：本物の reCAPTCHA 画像で、人間の正答率（文献値 ~82%）に匹敵する判別性能。**

| 評価データ | 正例/負例 | zero-shot AP | fine-tuned AP | 差 |
|---|---:|---:|---:|---:|
| 晴れの通常写真 (img) | 11/99 | 1.000 | 0.984 | −0.016 |
| 雨の写真 (img_bus_rain) | 50/52 | 0.978 | 0.943 | −0.035 |
| **本物 reCAPTCHA (real_recaptcha)** | 6693/6693 | 0.875 | **0.906** | **+0.031** |

- 本物での **FT 最大F1 = 0.827** で、**人間の正答率 ~82% を上回る水準に到達**。
- 劣化のない通常写真では zero-shot が勝つが、**本物の reCAPTCHA では FT が逆転して上回る**。
  この逆転は劣化つき水増しで学習した複数モデル（旧フィルタ +0.021 / 新フィルタ100ベース +0.036 / 同300ベース +0.031）すべてで再現しており頑健。
- 統計的裏付け：ペアド・ブートストラップ（10,000回）で ΔAP の95%CIは [+0.015, +0.027]（旧フィルタモデルで測定）。
  **0を跨がない＝評価セットの偶然ではない**（現行300ベースモデルでのCIは再計測中）。

### フィルタの妥当性（前回指摘への回答）

1. **本物を観察**：実際の reCAPTCHA v2 画像29,568枚（HuggingFace `nobodyPerfecZ/recaptchav2-29k`）を導入し目視確認。
   劣化の実態は「低解像度・ぼけ・JPEGブロックノイズ」で、**雨だれの線や夜の暗さは存在しない** → 旧フィルタ（暗く＋白線）は的外れだったと確認。
2. **本物寄りに作り直し**：新フィルタ＝低解像度化＋ぼかし＋彩度低下＋JPEG低品質再圧縮。
3. **FID で定量評価**（同じクリーン bus 画像にフィルタだけ変えて適用し、本物 bus 6,693枚との分布距離を比較）：

| フィルタ | FID（↓小さいほど本物に近い） | 判定 |
|---|---:|---|
| clean（劣化なし・基準） | 206.7 | — |
| 旧・夜（暗く） | 179.2 | 少し近づく |
| 旧・雨（暗く＋白線） | **381.5** | **逆効果**（本物に無い線で遠ざかる） |
| **新（低解像度＋ぼけ＋JPEG）** | **164.5** | **最も近い＝妥当** |

4. **アブレーション**（劣化条件だけ変えて本物 AP を比較）：
   劣化なし学習は 0.842 で zero-shot にすら負ける → **劣化つき水増し自体が転移に効くことは確定**。
   ただし新旧フィルタ間の AP 差は実行間ばらつき（±0.015）に埋もれており、「新フィルタだから AP が上がった」は**まだ言えない**（§4参照）。
   フィルタが本物に似ていること自体は FID で独立に示せている。

## 3. テスト・学習データの分離

3重に分離している。

1. **ソースの分離**：学習は COCO 2017 由来＋合成劣化のみ。評価は別ソースの本物画像3セット（img / img_bus_rain / real_recaptcha）。
   **評価画像・本物 reCAPTCHA 画像は学習に一切使っていない**。合成劣化は学習の水増し専用で、評価には混ぜない。
2. **train/val のリーク防止**：原本と劣化版は同じ景色なので、ファイル単位のランダム分割だと同一景色が train と val に跨がり点数が甘く出る。
   `split_train_val.py` は**元画像ID単位**で分割し、同一景色の3枚は必ず片側にだけ入る。
3. **再現性**：シード42固定・依存は uv.lock 固定。同じ手順で同じ分割・同じ学習になる。

## 4. 現在の問題点

1. **フィルタ種類の寄与が AP では未決着**：同一条件でも実行間で AP が ±0.015 ぶれることが分かり（同条件2回学習で 0.911 / 0.896）、
   新旧フィルタの差がこのばらつきに埋もれる。→ 同一ベース・複数シードで学習して決着させる（次回の最優先）。
2. **git 管理外の生成物がマシン間で不同期**：モデル（.pth）と dataset/ は git 管理外のため、別マシンの再学習が手元に反映されず、
   検証時に旧モデルを新モデルと取り違える事故が起きた（検出済み・ドキュメントは訂正済み）。
   → モデルファイルに学習日・データ設定のメタ情報を残す等の再発防止策を入れる。
3. **CI の再計測が必要**：ブートストラップCIは旧フィルタモデルでの測定値。現行300ベースモデルで測り直して +0.031 に信頼区間を付ける。
4. **評価セットが人工的に1:1**：real_recaptcha は bus/nonbus を同数に揃えており、実運用の出現率と違うため AP の絶対値は実運用と一致しない
   （zero-shot と FT の比較の公平性には影響しない）。
5. **9マス本番デモが未確認**：`split_recaptcha.py`（3×3分割）＋`predict_recaptcha.py`（マスごと判定）を本物画像で通して発表用の絵を作る。
6. **bus は zero-shot でほぼ足りる問題**：FT の価値をより明確に示すなら、ImageNet に無い/弱いお題（消火栓・横断歩道・階段）への拡張を検討。
